# 部署

本文说明 Docker Compose、离线二进制包与 CI 构建。环境变量详见 [环境变量](环境变量.md)。

## Docker Compose

在项目根目录（需 Docker Engine + Compose v2）：

```sh
cp .env.example .env
# 可选：修改 BASE_ADMIN_PASSWORD；未设置时默认 ChangeMe123
docker compose up -d --build
docker compose ps
docker compose logs -f baseplatform
```

访问 `http://127.0.0.1:8181`（或 `.env` 中 `BASE_PUBLIC_PORT` 指定端口）。初始账号 `admin`，首次登录须改密。

### 常用操作

```sh
docker compose down              # 停止服务，保留数据卷 base-data
docker compose up -d --build     # 更新代码后重新构建
```

**不要**在保留数据时使用 `docker compose down -v`。升级前建议先在运维中心创建备份。

### 网络与安全

- 默认仅绑定本机（`BASE_BIND_ADDRESS=127.0.0.1`）。
- 局域网访问可设 `BASE_BIND_ADDRESS=0.0.0.0`。
- 公网部署须在前方配置 HTTPS 反向代理。
- 容器内以 UID/GID `10001`（用户 `baseplatform`）运行，监听 `0.0.0.0:8181`。
- 数据持久化于命名卷 `base-data`；宿主机目录挂载时须对该 UID/GID 可写。

### 镜像内容

包含 Go 二进制、前端静态资源、CA 证书、时区与健康检查工具。**不包含** MySQL/PostgreSQL 客户端、视频解码器或 AI 推理运行时。使用外部数据库时需自行注入 `BASE_DB_*` 并在镜像或挂载中提供 dump 工具。

### 手动构建镜像

```sh
docker build -t baseplatform:local .
# 推送至自有仓库（替换地址）：
docker buildx build --platform linux/amd64,linux/arm64 \
  -t YOUR_REGISTRY/baseplatform:VERSION --push .
```

健康检查请求 `/api/health/live`；综合健康见 `/api/health`。

## 二进制程序包

CI 或本地 `scripts/package.sh` 生成六平台包（Linux/macOS/Windows × amd64/arm64），内含：

- `baseplatform`（Windows 为 `baseplatform.exe`）
- `frontend/dist`
- `start.sh` / `start.bat`
- `DEPLOY.md`（本文摘要）

### 运行

macOS / Linux：

```sh
export BASE_ADMIN_PASSWORD='你的密码'   # 可选，默认 ChangeMe123
./start.sh
```

Windows PowerShell：

```powershell
$env:BASE_ADMIN_PASSWORD='你的密码'
.\start.bat
```

脚本自动设置 `BASE_FRONTEND_DIR` 与 `BASE_DATA_DIR`（默认为包目录下 `data/`）。监听地址与端口可通过 `BASE_HOST`、`BASE_PORT` 修改。

### 本地打包

```sh
cd frontend && npm ci && npm run build
bash scripts/package.sh linux amd64
bash scripts/package.sh windows arm64
```

产物输出到 `release/`，附带 SHA-256 校验文件。程序未经 Apple/Windows 代码签名或公证。

## GitHub Actions

`.github/workflows/build.yml` 在 push、PR 及手动触发时执行：

1. **前端**：Node 24 → 类型检查、测试、生产构建。
2. **后端**：竞态测试 + `go vet`。
3. **程序包**：六平台矩阵构建并上传 Artifact（保留 30 天）。
4. **Docker**：amd64 / arm64 原生 runner 分别构建镜像，验证健康检查、前端访问、数据卷持久化及无初始密码重启。

在 Actions → 对应运行 → Artifacts 下载 `baseplatform-系统-架构`。构建成功不等于所有目标操作系统均已现场验收。

## 跨平台编译

无 cgo 依赖，示例：

```sh
cd backend
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 \
  go build -o ../build/baseplatform-linux-amd64 ./cmd/baseplatform
```

或使用 `make build` / `make package`。

## 升级建议

1. 升级前在运维中心备份，或停服复制完整 `BASE_DATA_DIR`。
2. 替换二进制或重新 `docker compose up -d --build`。
3. 保留原数据目录与 `session.key`；不要混用不同实例的数据。
4. SQLite 恢复须停服并将 `BASE_DATA_DIR` 指向已验证的恢复目录，见 [运维与备份](运维与备份.md)。
