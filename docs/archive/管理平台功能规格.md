## 1. 功能对应

以下按功能模块整理需求与实现设计。参考的是功能组织与业务流程，不代表获得参考项目源代码，也不承诺兼容其全部 API。部分配置仅以截图呈现，本文不将未核实字段作为原项目事实。

| 功能 | 已确认能力 | 本项目实现设计 |
| --- | --- | --- |
| 添加摄像头 | 拉流、GB28181、推流三类接入 | 统一视频源管理，按阶段实现协议适配 |
| 拉流接入 | 名称、编号、协议、地址、厂商、备注、ONVIF 探测、转发 | 增加连接测试、分组、断流原因、密钥引用及流健康状态 |
| GB28181 | 国标设备接入、配置说明与厂商示例 | 独立接入适配器，注册、目录、心跳、通道与媒体会话管理；型号实测 |
| 推流接入 | 外部工具推送文件、USB 摄像头、屏幕等视频源 | 推流地址与授权管理；本地 MP4 回放测试 |
| 基础算法 | 模型类型、框架、引擎、设备、参数、类别、文件 | 模型仓库与版本管理，首期支持经过适配验证的 ONNX 分割模型 |
| 行为算法 | 内置行为规则与 API 类型扩展 | Go 规则执行器，首期实现抓斗临边/越界；扩展规则接口 |
| 业务算法 | 多个基础算法与一个行为算法组合，多种处理链路、实例配置 | 抓斗分割＋坑边识别＋越界规则组成版本化模板 |
| 添加布控 | 布控创建、OSD、扩展参数 | 摄像头绑定、区域、时间计划、运行节点、告警与显示配置 |
| 布控算法 | 业务算法绑定、区域绘制、大模型复核 | 可视化坑边配置及规则表单，复核功能作为扩展 |
| 大模型 | 服务地址、模型名称、密钥、超时、不同工具接入 | 可选事件复核服务，不阻塞首期实时几何告警 |
| 人脸 | 人员照片、人脸库更新与布控关联 | 记录为可选扩展；当前抓斗业务不启用 |
| 计划任务 | 定时任务与 Cron 配置说明 | 布控日历、录像计划、维护任务及执行记录 |
| 开放接口 | 接口章节和版本化接口文档下载入口 | 自有版本化 REST API、实时订阅、事件 Webhook；未逐项核对其完整接口包 |

账号权限、告警处理闭环、备份恢复等下文内容是本项目补全设计，不声称参考文档已经具备这些细节。

## 3. 核心业务流程

```mermaid
flowchart LR
 A[添加摄像头] --> B[连接测试与预览]
 B --> C[AI 生成坑边候选]
 C --> D[校准并发布边界]
 D --> E[选择抓斗越界业务模板]
 E --> F[设置时段与告警规则]
 F --> G[自检并启动布控]
 G --> H[实时分析与事件证据]
 H --> I[确认与处理]
 I --> J[关闭或标记误报]
 J --> K[样本复核与离线模型迭代]
```

布控自检校验视频可用、边界有效、模型版本可加载、运行后端可用、节点有容量和证据路径可写。保存草稿不等于成功启动；启动失败返回可操作原因，并保留其他摄像头的运行状态。

## 4. 视频管理

摄像头字段：自动编号、名称、项目、区域/分组、接入类型、主/子码流配置、厂商/型号、备注、启用状态及凭据引用。编辑流配置时记录版本，并检查是否改变视场，必要时使边界失效。

设备状态、媒体状态和分析状态独立展示。例如“设备已登记、视频离线、布控等待视频”，避免把网络可达误写成视频正常。错误至少区分认证失败、连接超时、无帧、编码不支持及解码失败。

删除采用停用/归档方式保留事件关联；有运行布控时先停止相关任务。批量导入执行字段校验和逐项结果反馈，不因一项失败回滚所有成功项。四路为当前验收规模，不在数据模型里写死四个编号。

国标接入单独负责信令与媒体适配，不默认 MediaMTX 已实现 GB28181。RTMP、HTTP-FLV、HLS 等输入按选定媒体适配器分别验证；输入协议与浏览器播放协议分开配置。参考项目的固定端口和参数不直接作为本平台默认值。

## 5. 坑边与布控配置

边界编辑页包含参考帧、采集时间、AI 候选、折线/多边形、坑内方向、监测范围及缓冲距离；允许撤销、重画、对比历史版本。折线端点外不参与越界，局部可见边不能自动补成完整坑口。

发布前检查坐标范围、最少点数、自交、坑内侧、参考流版本；保存原图尺寸与坐标变换。边界版本状态为草稿、已发布、已失效、已归档。回滚采用历史内容生成新版本，并重新校验当前画面适用性。

布控字段：名称、摄像头、业务算法版本、边界版本、分析频率、阈值、触发/恢复持续时间、时间计划、运行节点、录像策略、通知策略及 OSD。普通用户使用带单位的表单，扩展参数为有 schema 校验的高级设置，避免要求用户拼逗号字符串。

运行状态为草稿、待启动、启动中、运行中、计划外、暂停、故障、已停止。配置采用修订号，界面同时显示“期望版本”和“工作进程已应用版本”。发布新版本需工作进程验证并确认，失败保持上一个有效版本或显式停止；不能把数据库保存成功等同于运行生效。

暂停分析与静音通知分开：暂停后不再分析；静音期间继续记录事件。画面明确标出计划外和暂停，不能显示为正常。对已发生事件，暂停、丢帧或目标消失均不自动确认恢复。

## 6. 算法管理与四路调度

基础模型版本保存模型文件、摘要、适配器、输入输出 schema、类别、精度、预处理、运行后端、兼容平台、验证记录和状态。模型上传后依次校验、试加载、样例推理、人工发布；被布控引用的版本不可直接覆盖或删除。

行为规则以稳定标识和版本管理，首期内置 `grab_near_edge` 与 `grab_cross_boundary`。阈值归入布控配置，规则实现归入版本；导出事件必须能还原当时的模型、边界及规则配置。

业务模板首期提供“抓斗分割＋坑边识别＋越界判定”，保留组合结构但不预设所有模型能够任意串联。节点输入输出类型不兼容时拒绝发布。参考项目中的多种引擎与算法框架列为扩展适配清单，未经验证不宣称支持。

Go 主服务负责配置、权限、规则与事件；Go 推理工作进程调用 ONNX Runtime。每路独立队列与状态机，有限会话池共享 GPU，每路公平调度；节点报告实际后端、模型加载情况、分析 FPS、帧龄和队列丢弃量。

大模型复核为后续异步事件附加结论，明确“待复核、完成、失败/超时”。抓斗越界原始告警和证据不被覆盖，复核失败不当作无越界。首期无需外部大模型或上传现场画面。

## 7. 告警中心与证据

告警详情：事件编号、摄像头/项目、类别/级别、开始时间、最近证据、结束时间、现场状态、处理状态、轮廓与边界叠加、触发指标、模型/规则/边界版本、截图/录像、处理记录。

现场状态与人工处理状态分开：现场可以仍在越界，但值班员已确认收到；人工关闭不得改变算法检测结果。处理流程为“待确认 → 已确认 → 处理中 → 已关闭”，允许填写“真实事件/误报/无法确认”，关闭时必须有结论和说明。新事件仍正常提示。

事件写入、证据生成与消息推送异步执行：事件先持久化，证据显示生成中/可用/失败；不能因录像截取失败丢失告警。截图或录像过期时显示保留状态，不给损坏链接。连续事件按稳定事件 ID 合并，重连或进程重试不重复生成同一通知。

列表支持时间、摄像头、区域、级别、处理状态、复核结论筛选及分页。批量确认保留每项处理结果。下载与导出均检查数据权限；原始视频、叠加图片和复核说明分开保存。

## 8. 基础功能补全

| 模块 | 必要行为 |
| --- | --- |
| 登录与会话 | 首次管理员初始化、登录/退出、个人资料、修改密码、失败限速、会话撤销；无公共默认密码 |
| 用户与角色 | 新建/禁用用户、分配角色、菜单与操作权限、项目/分组数据范围；服务端强制校验 |
| 建议角色 | 管理员、值班员、算法工程师、运维、只读；角色可调整，按实际权限授权 |
| 权限细分 | 预览、回放、下载、处理告警、编辑边界、发布模型、启停布控、管理用户分开控制 |
| 操作审计 | 登录、权限变更、模型发布、边界修改、布控启停、告警处理、导出及恢复；记录操作者和变更摘要，密钥脱敏 |
| 通用列表 | 查询、筛选、排序、分页、空态、加载态、错误重试；操作结果反馈，跨页批量范围明确 |
| 字典与参数 | 级别、分组、展示参数和保留策略；字典编码稳定，已引用项只能停用 |
| 计划任务 | 可视化时段与高级表达式、时区、下次执行时间、运行记录、超时与失败原因 |
| 备份恢复 | 配置/数据库/模型清单，证据可选；备份校验、恢复前检查与恢复演练，明确密钥恢复方式 |
| 系统信息 | 软件/模型/运行库版本、健康状态、脱敏诊断包与升级说明 |

定时任务仅允许内置动作，如布控启停、录像、清理、备份和报表，不开放任意 shell。进程重启后按当前日历恢复布控期望状态；错过的录像无法补录，维护任务依策略补一次或跳过并记日志。单机也需要任务互斥和幂等，避免重复清理或重复发通知。

通知投递与事件分开保存；Webhook 使用稳定投递 ID、签名、超时、指数退避和有限重试，超过上限进入失败列表并允许重试。推送失败不影响主分析链路。

## 9. 录像、报表与运维

录像计划支持关闭、按时段、连续与仅事件模式，配置每路保留时间与总容量上限；事件证据和普通录像采用不同清理策略。删除前检查事件保留/锁定状态。统计使用视频实际可用区间，不把播放器打开时间作为在线时长。

回放支持摄像头＋日期筛选、时间轴、缺口标记、事件定位和区间导出。本地证据回放为 P0；远程检索 NVR 历史录像依厂商/国标能力作为 P1 单独对接。

报表区分事件数量、人工确认数量、人工误报数量、不可判定时长和视频离线时长。人工标记误报比例是运营指标，不等于模型总体误报率；没有人工真值不能生成召回率。统计时间以 UTC 存储、按配置时区展示。

运维页面按摄像头展示实际分析频率与结果帧龄；按节点展示 CPU/GPU/内存/磁盘和推理后端。任何不可判定、断流、节点故障、证据失败均可追溯原因。磁盘满时报告录像故障、尽可能继续分析并保留最小事件元数据；数据库无法持久化必须报警，不能继续宣称告警已保存。

## 10. Go 实现边界与数据模型

采用模块化单体主服务＋独立推理工作进程，首期不引入微服务集群。主服务按 `identity`、`camera`、`boundary`、`algorithm`、`deployment`、`event`、`recording`、`notification`、`scheduler`、`system` 分包；媒体进程由生命周期管理器监测与重启。

数据库首期选定一种实现并使用版本迁移，不同时维护多套行为；单机可选 SQLite，集中部署可选 PostgreSQL。具体驱动需核对跨平台依赖。前端采用独立 Web 管理端，静态产物可随 Go 服务打包，客户端无需安装原生界面。

| 数据实体 | 关键关系 |
| --- | --- |
| users / roles / permissions / role_bindings / data_scopes | 用户、角色、操作和项目/分组范围 |
| projects / camera_groups / cameras / stream_profiles | 项目分组与视频源，凭据单独引用 |
| boundary_versions | 摄像头、参考帧、坐标、流版本、发布人和有效状态 |
| models / model_versions / rule_versions / business_versions | 模型资产与业务组合版本 |
| deployments / deployment_revisions / runtime_status | 布控期望配置、历史版本和实际生效状态 |
| nodes / model_sessions | 推理节点、可用后端、容量和模型会话 |
| events / event_updates / event_actions / evidence | 现场事件、状态变化、人工处置与证据 |
| recording_plans / recording_segments | 录像计划、时间范围与文件索引 |
| schedules / job_runs | 任务定义和执行结果 |
| notification_policies / deliveries / api_tokens / audit_logs | 通知、接口访问和审计 |

事件引用不可变配置快照；历史数据不依赖可随时编辑的当前配置。所有服务端接口按授权范围查询数据，图片、录像、WebSocket 订阅和导出任务执行相同权限规则。

接口分组统一为 `/api/v1`：认证与用户、摄像头/连接测试、边界候选与发布、算法版本与验证、布控修订与启停、事件处理、录像查询与导出、节点状态、计划任务及审计。实时订阅带流会话、帧 ID、PTS、事件 ID 和配置版本；分页、错误码、异步任务 ID、请求追踪与并发修订冲突统一处理。

这套接口为自有协议；如后续需要替换参考产品且兼容其现有客户端，应另外逐项核对其 OpenAPI 包并建立兼容测试。

| 里程碑 | 可验收结果 |

必须覆盖的验收场景：

1. 四路同时运行；单路断网不拖垮另外三路，恢复后不使用旧帧和失效边界。
2. 模型不可用、机位变化、摄像头认证失败、磁盘不足都有明确状态及原因。
3. 新边界/模型/规则发布失败时，界面准确显示实际生效版本。
4. 真实越界触发一次持续事件，证据和版本可追溯；人工确认不解除现场越界。
5. 只读用户无法写操作，越权访问事件/录像/下载/实时订阅被拒绝。
6. 重启恢复布控与计划；不会重复发出同一事件通知，不会把计划外时段记为正常监测。
7. 备份在独立测试环境成功恢复，并抽检用户、配置、模型引用和证据索引。
8. 模拟数据必须标为演示；模型未就绪时不伪造正常率、告警或检测轮廓。

上一份方案的算法原型工期不代表本完整管理平台工期。需按这些里程碑、人员配置和 P1 范围重新排期。
