源码来自独立的后端 / 前端仓库工作副本（只读拷贝进本仓库，未回写原目录）。文件对应关系见仓库内 `migration-source-map.json`；目标侧可含迁移后的适配改动，不以源仓库本地绝对路径或瞬时 HEAD 作为文档依据。

## 复用与适配

| 内容 | 处理 |
| --- | --- |
| 用户、部门、系统参数、日志处理器 | 从原文件迁移，调整导入路径、依赖、错误处理和参数校验 |
| JWT、bcrypt、验证、分页、审计与登录限流 | 从原实现迁移，登录 Cookie 改为独立命名；增加会话版本 |
| 数据模型 | 提取 User、Department、SysConfig、SysLog、AuthRevokedToken；不迁入文件业务表 |
| 用户、部门、日志页面 | 复用原 Vue 页面，清理令牌、邮件重置、头像上传和授权服务入口 |
| 请求封装、Pinia、分页/弹窗/头像、主题及样式 | 复用原模块；会话存储 key 独立命名 |
| 登录、布局、个人中心、概览、角色说明、设置页面 | 基于原 API/组件与 Tabler 风格适配，解除网盘和智能体依赖 |
| 配置、数据库启动、入口与路由 | 新建最小 Go 启动装配，默认仅监听本机，首次管理员密码自行配置 |

后端仍使用原页面的 `/api/...` 路径，以减少迁移改动；未来视频模块可使用 `/api/v1`，当前不是语雀参考产品的 API 兼容实现。

## 迁移过程中修正

- 角色变更、禁用与密码修改后旧会话失效；登录退出使用独立 HttpOnly Cookie。
- 普通用户不能访问基础管理 API；删除类操作仅超级管理员。
- 禁止修改本人管理角色、禁用本人及普通管理员修改超级管理员。
- Cookie 写请求检查同源 Origin；Vite 代理保留 Host，后端不信任未配置代理的来源 IP。
- 部门上级可以清空，并校验间接循环；用户部门可清空。
- 内置安全/品牌设置无法通过通用参数接口绕过专用校验。
- 凭据不复制、不提供固定默认密码、不在现有数据库启动时重置管理员。
- 不再保存 SMB 用途的 NTLM 密码哈希。

#### 迁移适配要点

- **个人令牌**：简化为令牌继承用户角色权限，不含源项目的文件存储范围权限（源项目 PAT 与挂载/路径/读写位深度耦合，视频 AI 平台无此体系）。令牌明文仅在创建时返回一次，存储仅保存 SHA-256 hash。网关开关 `settings.Gateway.PersonalTokensEnabled` 控制是否允许 PAT 认证。
- **计划任务**：内置任务仅保留 NTP 同步、定期备份、LDAP 同步（LDAP 同步为占位，待部门同步适配后完善）；移除了源项目的上传清理任务（视频 AI 平台无上传会话清理需求）。命令执行保留白名单（`rsync`/`tar`/`gzip`/`zstd`/`cp`/`mv`）和路径根校验，可通过环境变量 `SCHEDULE_BIN_ALLOWLIST` 和 `SCHEDULE_PATH_ROOTS` 扩展。
- **登录流程**：支持验证码（全局启用或账号连续失败 3 次后强制）、TOTP 二次验证（临时令牌流程）、LDAP 回退（本地认证失败后尝试 LDAP，首次登录自动创建本地用户记录）。
- **OAuth**：支持 GitHub、Microsoft、Google 及自定义提供商；回调地址通过环境变量 `BASE_PUBLIC_URL` 配置；状态签名复用 `security.SignState/VerifyState`。
- **数据库**：`AutoMigrate` 已包含 `OAuthAccount`、`PersonalAccessToken`、`ScheduleCommand`、`ScheduleJob` 表。
- **安全**：移除了 `SaveSecurity` 中阻止启用验证码和双因素的临时限制；管理员可通过安全设置页面启用验证码和 TOTP。

#### 功能说明

**验证码（Captcha）**：
- 三种类型：纯数字、字母+数字、算术运算
- 全局启用或账号连续失败 3 次后强制
- 图片混淆（XOR 异或）提高 OCR 门槛，前端自动还原
- 管理员可在安全策略面板配置所有参数并实时预览
- 社区版可用（无授权限制）

**双因素认证（TOTP/2FA）**：
- 登录流程：密码验证 → 若已启用 TOTP 则返回临时令牌 → 用户输入动态验证码 → 完成登录
- 个人设置页：用户可自行启用/禁用 TOTP（生成二维码→扫码→输入验证码确认）
- 管理员强制：安全策略面板可开启"要求管理员登录时验证 TOTP"（旗舰版功能）
- 管理员强制开启后，管理员用户无法自行关闭 2FA

**规格依据**：§2"通知管理 | 站内通知与阅读状态 | P0"；§8"通知投递与事件分开保存；Webhook 使用稳定投递 ID、签名、超时、指数退避和有限重试，超过上限进入失败列表并允许重试"

**设计要点**：

### 与视频 AI 业务的解耦原则

以上基础功能均与视频 AI 业务解耦：
- 字典管理：通用枚举，视频 AI 的告警级别/设备类型只是字典的一种应用
- 通知系统：通用事件通知，视频 AI 的越界告警只是通知的一种事件类型
- RBAC：通用权限，视频 AI 的"启停布控"只是权限点之一
- 数据范围：通用数据隔离，视频 AI 的"项目/区域"只是数据范围的一种维度
- 审计/健康检查/API 日志：纯平台运维功能，与业务无关

实施时应将业务相关的权限点编码、事件类型、字典分类作为配置或注册项，不硬编码到基础模块中。

**判定规则**：数据库不可达 → `down`；磁盘使用率 ≥95% → `down`，≥85% → `degraded`。`down` 时返回 HTTP 503。`/api/health/live` 仅返回 `{status: ok}` 用于存活性探测。

**内置角色与默认权限**：
- `superadmin`：全部权限（代码级放行，不依赖权限表）
- `admin`：除删除类（`*:delete`）与角色管理外的管理权限
- `user`：`dict:list`、`storage:list` 等只读权限

**数据范围策略**（取用户所有角色中权限最大者）：
- `all`：不添加过滤条件（superadmin 始终为 all）
- `project`：`project_id IN (用户所在项目)`，无项目时返回空
- `dept`：`department_id = 用户部门ID`
- `dept_and_sub`：`department_id IN (用户部门及所有下级部门)`
- `self`：`user_id = 当前用户ID`
- `custom`：暂按 `dept_and_sub` 处理，后续可扩展为指定部门集合

**`ApplyDataScope` 使用方式**：调用方传入 `ScopeOptions{UserIDColumn, DeptIDColumn, ProjectIDColumn}` 指定资源表对应的列名，由服务自动注入条件。例如项目列表按 `owner_id` 过滤。项目列表本身已应用数据范围。

**项目成员角色**：`owner`（负责人）、`admin`（管理员）、`member`（成员）。创建项目时创建者自动加入为 owner。

**接口**：
- 项目：`GET/POST/PUT/DELETE /api/admin/projects`（删除需超级管理员）
- 成员：`GET/POST /api/admin/projects/:id/members`、`PUT/DELETE /api/admin/projects/members/:mid`

**约束**：项目编码全局唯一；同一用户在同一项目中只能有一条成员记录；项目列表按当前用户数据范围过滤，普通用户仅可见自己负责或参与的项目。
