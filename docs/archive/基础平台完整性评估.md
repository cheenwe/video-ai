# 基础平台完整性评估

> 2026-09-16 更新：下文保留历史记录。当前状态以 [基础平台修复与验收](基础平台修复与验收.md) 为准；固定角色门禁、外部指令、内存通知与在线覆盖恢复等历史描述已被替代。

评估日期：2026-09-15。依据本次读取的工作目录代码、路由、现有测试及隔离副本中的权限复核；不以旧迁移说明或菜单数量作为完成依据。评估期间不修改业务代码、现有账号或运行数据库，也未执行恢复、外部通知或 2FA 绑定。

## 结论

基础平台已具备较完整的模块结构，可以继续开发和联调，但尚未达到正式交付标准。主要问题是已配置功能未在服务端强制生效、部分流程未形成闭环，以及新模块缺少验收覆盖。不能给出有依据的“完成百分比”。

当前代码比 README 和首批迁移说明新增了大量模块，文档已落后。计划任务、备份、RBAC 等应标记为“已有实现、待修正与验收”，不能继续标记为“尚未迁移”，也不能直接标记为“完成”。

## 优先修复的问题

### 1. P0：角色权限配置未强制作用于接口（已隔离复核）

`backend/internal/middleware/auth.go` 定义了 RequirePermission，但当前路由未调用它；管理接口统一使用 RequireAdmin。前端路由也主要检查 isAdmin。

在隔离数据库中，将管理员角色的权限清空，同时保留该账号的 admin 标识，GET /api/users 仍返回 success=1。普通账号即使分配自定义管理权限，也仍会被固定管理员门槛拦截。

应按动作接入权限点，前端菜单/按钮跟随权限；删除、恢复、角色授权等操作须明确服务端权限。当前备份 UI 限制超级管理员，但接口只有普通管理员门槛，前后端不一致。

### 2. P0：自定义字段跨实体读写缺少授权（已隔离复核）

`backend/internal/server/server.go` 将 /api/cf-data/:module/:entityId 的读写放在仅需登录的分组；`backend/internal/handlers/custom_field.go` 校验模块、字段和值，但未校验实体归属及操作者权限。

隔离测试中，普通用户成功更新了管理员实体的自定义字段，并确认值已经持久化。应按模块解析目标实体、验证存在性、检查资源权限与数据范围，批量读取执行同样规则。

### 3. P0：初始化密码与首次改密存在服务端缺口（已隔离复核）

`backend/internal/database/database.go` 当前默认创建三个共用固定初始密码的账号，且初始化跳过密码策略。与 README 中“无默认密码”的描述不一致。

MustChangePassword 目前用于前端弹窗，认证中间件没有将此状态限制为“只能改密/退出”。隔离测试确认该标记为 1 的管理员仍能读取用户列表。

应由服务端限制未完成初始化的会话权限；采用部署时指定密码或一次性初始化凭据，并同步文档。

### 4. P0：TOTP 绑定密钥发送到外部二维码服务（代码确认）

`backend/internal/services/totp.go:37` 将完整 otpauth URI 放入 api.qrserver.com 的 URL。该 URI 含 TOTP 密钥，个人中心将此 URL 用作图片地址。加载二维码会向外部服务发送密钥。

应在浏览器本地或后端本地生成二维码。另需补充动态验证码尝试限速、临时凭据重放防护，以及“管理员强制 2FA”在登录和关闭 2FA 接口中的强制执行。本次未加载或发送真实绑定密钥。

### 5. P0：备份恢复不能保证可靠恢复（代码确认，未进行破坏性实测）

`backend/internal/services/ops_backup.go` 创建备份时既遍历运行中的数据目录，又生成 SQLite 一致性快照；快照归档名为 db-dump.sql。SQLite 恢复分支没有将该快照作为数据库恢复源，而是认为文件覆盖已完成。

恢复过程直接覆盖运行目录，未停止数据库读写或处理 WAL；部分文件创建、复制、关闭错误被忽略。数据库导出失败只记录错误字段，流程仍可能报告成功。缺少完整校验、临时恢复、原子替换及失败回滚。

应先完成离线或受控维护模式恢复、校验和版本检查，再做独立环境恢复演练。正式验收以恢复后的用户、配置、角色及数据抽检为准。

### 6. P1：项目数据权限仅部分接入（代码确认）

ApplyDataScope 当前仅用于项目列表；项目更新和成员操作直接按 ID 查询。项目范围列表没有传入 ProjectIDColumn，实际回退到 owner_id，项目成员可能看不到应有项目。

数据范围缺少适用列时部分分支直接返回未过滤查询。应统一资源授权，缺少范围信息时拒绝或返回空集，并明确多个角色的数据范围合并规则。

### 7. P1：通知和 Webhook 缺少业务闭环（代码确认）

当前业务代码未找到 EventBus.Emit 调用。即使发出事件，EventBus 的用户 ID 为 uint，而 onEvent 按 float64 断言，通知创建分支不会按预期执行。

重试依赖内存 goroutine 和 sleep，没有看到服务启动时恢复 pending 投递的流程；手动重试重新生成投递 ID。需接入实际事件生产者、持久化待投递任务及稳定事件/投递标识，再验证重启续投和去重。

### 8. P1：计划任务生命周期与平台依赖未收口（代码确认）

路由创建时直接启动调度器并忽略 Start 错误；未将 Stop 纳入主进程退出生命周期。源项目的 rsync/tar/gzip 等指令预置也已迁入，与原规格“只允许内置动作”的范围存在偏差，且目标机器不一定安装对应程序。

需明确动作白名单和配置范围、启动错误处理、退出等待、每任务时区、错过执行策略、运行中重复触发行为及 Windows/Linux 实测。

## 已执行验证与限制

- 当前工作目录：go test ./... 通过；前端 npm run typecheck 通过；npm test 通过（2 个测试文件、4 项测试）。
- 当前后端现有测试主要覆盖首批用户/部门/会话/配置流程；新增 services、scheduler、storage 等包无直接测试文件。
- 隔离副本复核：清空角色权限仍可访问管理 API；首次改密标记未限制 API；普通用户可持久化修改其他用户的自定义字段。测试通过表示成功复现当前缺陷，不表示权限安全验收通过。
- 本次未进行所有新增页面的浏览器验收、外部邮件/LDAP/OAuth 联调、真实数据库恢复、Linux/Windows 运行或持续负载测试。

## 建议验收顺序

1. 先关闭上述 P0 缺口：授权、跨实体访问、首次改密、TOTP 密钥和恢复一致性。
2. 再补 RBAC/项目数据范围完整流程、通知投递、任务生命周期、审计与密钥脱敏。
3. 对每个已迁移模块执行“创建→查询→修改→停用/删除→越权拒绝→失败反馈→重启保持”验收。
4. 完成备份恢复演练、目标平台运行检查，并同步迁移文档后，将基础平台标记为可交付。
5. 摄像头、坑边、算法、布控、告警和录像属于后续视频业务；不能计入当前基础平台已完成范围。
