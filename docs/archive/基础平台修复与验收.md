# 基础平台修复与验收

日期：2026-09-16。本次针对《基础平台完整性评估》的八类问题实施修复，测试使用临时数据库及本机测试服务；未修改 NextFile 源项目或正式账号。

## 修复结果

| 问题 | 当前实现 |
| --- | --- |
| RBAC 未约束接口 | 管理接口按动作校验权限；自定义角色生效，停用角色不授予权限；启动不覆盖已有授权；菜单、配置页签及主要操作入口同步过滤。角色授权及敏感运维操作仍要求超级管理员。 |
| 自定义字段越权 | 按实体与数据范围校验单条读取、写入、批量查询；仅开放已有授权适配的用户、部门、项目模块。 |
| 默认密码、首次改密 | 空数据库必须显式配置管理员密码，只创建一个初始管理员；服务端限制未改密账号，改密后撤销旧会话。已有账号不自动重置。 |
| TOTP | 二维码本地生成；挑战绑定会话版本，账号/IP 限流，一次性挑战与时间步防重放；强制绑定由服务端执行；OAuth 已启用 TOTP 的账号也进入二次验证。 |
| 备份恢复 | SQLite 一致性快照、格式版本与 SHA-256 校验；失败返回错误；恢复仅解压到新的独立目录并检查数据库完整性，不覆盖运行库。 |
| 数据范围 | 用户、部门、项目及项目成员操作接入范围检查；多个角色范围取并集；缺少资源维度时拒绝访问；移除未实现的 custom 范围选项；负责人转移同步更新成员。 |
| 通知与 Webhook | 审计/任务事件落库；通知去重，投递持久化、到期重试、重启续投，手动重试沿用稳定投递编号；修正 SQLite UTC/本地时间比较。 |
| 计划任务与生命周期 | 内置数据库检查、会话清理、备份；预置任务默认停用；明确时区、并发上限、运行互斥、持久执行记录、取消与退出等待；错误上传调用方；旧外部指令/占位任务停止执行。 |

## 部署与恢复约定

1. 首次启动设置 `BASE_ADMIN_PASSWORD`，首次登录完成改密。已有数据库不会被启动逻辑改写密码；历史弱密码账号须通过正常账户管理流程处理。
2. 单实例运行。调度器没有分布式锁；重启跳过错过的计划时间，将遗留运行状态记为失败。任务需管理员自行启用。
3. SQLite 在运维中心创建备份；恢复操作返回 `prepared` 与独立目录路径。保留当前数据目录，停止服务，设置 `BASE_DATA_DIR` 指向准备目录后重启并验收。若显式设置了数据库路径或外部密钥，也须保持配置一致。
4. 新备份使用格式 2，恢复需要归档和配套清单；旧格式不自动恢复。下载归档不等于已完整迁移恢复材料，应一并保留备份目录中的清单。当前没有独立离线恢复 CLI。
5. MySQL/PostgreSQL 备份依赖原生客户端；不支持将外部库直接在线恢复。恢复须使用独立数据库和原生工具。本轮未进行外部数据库容灾演练；仅完整 DSN 配置的外部数据库备份会明确拒绝，避免误备份其他连接。
6. Webhook 为至少一次投递；接收方应按稳定投递编号去重。业务写入与审计不是一个全局事务；持久事件保证从已落库事件开始续投，不承诺业务操作到外部系统的严格恰好一次交付。

## 尚未验收的系统边界

OAuth/LDAP、SMTP、外部存储、商业授权与升级接口需要真实服务联调；本次没有发送外部消息或执行真实升级。历史账户治理、长期运行、目标操作系统和外部数据库恢复仍需部署验收。四路摄像头接入、抓斗识别、坑边检测与越界判定仍属于后续视频算法阶段，本次不计为完成。
