# 运维与备份

## 运行约束

### 单实例

默认单进程 + SQLite，**不支持**多实例同时写同一数据库。计划任务调度器无分布式锁；进程重启后：

- 跳过错过的 Cron 触发时间；
- 将遗留的「运行中」任务记为失败；
- 预置内置任务默认**停用**，需管理员在计划任务中手动启用。

### 数据目录

生产环境固定 `BASE_DATA_DIR` 绝对路径，目录内至少包含：

| 路径 | 说明 |
| --- | --- |
| `baseplatform.db` | SQLite 主库（WAL 模式下可能有 `-wal` / `-shm`） |
| `session.key` | 未设置 `BASE_SECRET_KEY` 时自动生成 |
| `avatars/` | 用户头像 |
| `storage/` | 本地存储根 |
| `backups/` | 运维中心生成的备份 |

更换机器或恢复时，须整体迁移数据目录并保持 `session.key` 一致，否则已有会话失效。

## 备份

在 **运维中心** 创建备份，生成：

- `baseplatform-{id}.tar.gz` — 归档
- `baseplatform-{id}.manifest.json` — 清单（格式版本、SHA-256 校验）

SQLite 备份采用一致性快照。新备份使用**格式 2**；恢复需要归档与配套清单，旧格式不自动恢复。

### 外部数据库

MySQL/PostgreSQL 备份依赖 `mysqldump` / `pg_dump`（可通过 `BASE_DB_DUMP_BIN` 指定路径）。**不支持**将外部库在线恢复到运行中实例；须使用独立库与原生工具。未完整配置 DSN 的外部库备份会被明确拒绝。

### 手动备份

停服后复制整个 `BASE_DATA_DIR` 是最简单的离线备份方式。

## 恢复

运维中心「恢复」操作**不会覆盖**当前运行库，而是：

1. 校验备份归档与清单；
2. 解压到新的独立目录；
3. 检查 `baseplatform.db` 完整性；
4. 返回 `prepared` 状态与目标路径。

### 切换至恢复数据

1. **停止**服务；
2. 保留当前数据目录（以便回滚）；
3. 将 `BASE_DATA_DIR` 指向恢复准备目录；
4. 若曾显式设置 `BASE_SECRET_KEY` 或外部数据库 DSN，须与备份来源一致；
5. 重启并验收登录、配置与关键业务数据。

当前没有独立离线恢复 CLI；下载 tar.gz 不等于完整迁移，请一并保留 manifest 文件。

## Webhook 与通知

- 投递为**至少一次**；接收方应按稳定投递编号去重。
- 业务写入与外部 Webhook **不在同一全局事务**；持久化事件保证从已落库事件续投，不承诺恰好一次交付。
- 站内通知对审计/任务等事件去重；服务重启后继续未完成投递。

## 安全运维

| 场景 | 行为 |
| --- | --- |
| 首次部署 | `admin` + `BASE_ADMIN_PASSWORD`（默认 `ChangeMe123`），登录后强制改密 |
| 改密 / 禁用 / 角色变更 | 撤销该用户旧会话 |
| TOTP | 本地二维码；强制绑定由服务端执行；OAuth 账号启用 TOTP 后同样二次验证 |
| 备份下载 | 检查权限；归档含数据库与配置，请妥善保管 |

历史弱密码或多余账号须通过用户管理流程治理，启动逻辑**不会**重置已有账号密码。

## 健康检查

| 端点 | 用途 |
| --- | --- |
| `/api/health/live` | 存活探测（Docker HEALTHCHECK 使用） |
| `/api/health` | 含数据库、磁盘等综合状态 |

## 其他

以下能力需要真实外部服务联调，开源仓库内仅完成接口与 UI：

- OAuth / LDAP / SMTP 端到端
- 外部对象存储与云盘 OAuth
- 商业授权服务器在线激活（默认 `https://license.nextfile.cn`）
- 在线升级包替换
- Linux/Windows 长期运行与外部数据库容灾演练
